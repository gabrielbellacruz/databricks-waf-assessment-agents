FAQ

The things people ask most about the agents.

Data & privacy

Do the agents read the data in my tables?

No. Agents read metadata and telemetry only — system tables, Unity Catalog information schema, and job/pipeline/cluster configuration. Findings store bounded, non-sensitive samples such as counts and object names, never rows of your data. Results are shared org-wide within your workspace, which is why evidence is kept non-sensitive by design.

Does any of my data leave my Databricks account?

No. The agents run inside your workspace as the app's service principal, and LLM-judged checks call a model-serving endpoint within your Databricks account through AI Gateway. Nothing is sent to an external service.

Answers & accuracy

Why is a question marked "Unknown / needs review"?

One of three reasons: there's no check for that question yet; the check ran but the evidence was too thin to judge; or the check couldn't read a signal it needed (often a missing system-table grant). Unknown is deliberately distinct from Answer later — it means the agent is deferring to you, not that you skipped it. See Troubleshooting if every question is Unknown.

How accurate are the agent's answers?

Deterministic checks report hard facts (High confidence). LLM-judged checks are graded proxies and are capped at Medium confidence — strong signals, but you should confirm them. Every finding shows its rationale and evidence so you can check the reasoning, and you always set the final status. See Verdicts & statuses.

Which model do the agents use?

LLM-judged checks call a Databricks model-serving endpoint, configurable at deploy time (it defaults to a Claude model served in your workspace). If none is configured, LLM-judged checks return unassessed and only deterministic checks produce verdicts.

Running & workflow

Can I re-run an agent after fixing something?

Yes. Re-run a layer's agent any time to refresh its findings as your workspace changes, then review what moved. Re-running replaces that layer's previous agent findings.

What happens when I add a new WAF question?

Nothing breaks. Questions live in data (waf-data.json) and checks are keyed to question ids, so a question with no check simply comes back as needs review until a check is written for it.

Can I run agents locally during development?

The full agent flow only runs in the deployed App (it needs the service principal, the Jobs, Lakebase and the serving endpoint). For development, an agent can be run as a dry run that prints its findings as JSON instead of writing to Lakebase. The offline check test suite needs no workspace at all — see CONTRIBUTING.md.
