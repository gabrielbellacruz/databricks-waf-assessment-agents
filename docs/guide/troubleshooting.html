Troubleshooting

Common symptoms, what causes them, and how to fix them.

Every question comes back Unknown

Likely cause: the service principal can't read the system tables — either the SELECT grant is missing or the system schemas are disabled.

Fix: have a metastore admin grant the app SP SELECT on system.information_schema, system.access, system.billing, system.compute, system.query, system.lakeflow, system.serving and system.ai_gateway, and enable any system schemas that are off by default. See the grant reference.

LLM-judged questions are all "unassessed"

Likely cause: no model-serving endpoint is wired, or the SP can't reach it.

Fix: confirm the assessment model / serving endpoint is configured for the deployment and that the app SP has query access to it through AI Gateway. Deterministic checks still run without it.

The run is stuck showing "running"

Likely cause: the Job died before it could post results (for example an out-of-memory kill), so no completion was ever recorded.

Fix: the app reconciles a run against the Jobs API and will mark it failed once the Job run finishes. Check the Job run in the workspace for the underlying error, then re-run the layer's agent.

The agent can't be triggered / the button does nothing

Likely cause: that layer has no Job configured, or you're not running the deployed App (agents don't trigger locally).

Fix: confirm the layer's agent Job was deployed by the bundle and its job-id environment variable is present in the App, then trigger again from the deployed App.

Findings look thin or miss objects I expected

Likely cause: scope. If you selected specific catalogs, checks only evaluate those; some signals also depend on the SP being able to see the relevant objects.

Fix: widen the catalogs in scope (or leave them unset to use every catalog the principal can see) and confirm the SP has visibility of the jobs, pipelines and clusters you expect, then re-run.

An uploaded document doesn't seem to influence the answers

Likely cause: only LLM-judged checks read uploaded docs, the judge weighs documents below hard workspace signals, and very large uploads are size-capped.

Fix: expect docs to move LLM-judged verdicts, not deterministic ones; when the judge does use a document it attaches the excerpt it cited to the finding, so check the evidence to see what was used. See Uploaded documentation.

Still stuck? The Databricks App writes agent progress and errors to its logs — check them first (databricks apps logs waf-assessment), then open an issue with what you expected, what happened, and the relevant log lines.
