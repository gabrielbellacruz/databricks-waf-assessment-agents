System tables & signals

Everything an agent reads is workspace metadata and telemetry — never the contents of your tables.

The bulk of the evidence comes from Databricks system tables; configuration the system tables don't expose is read from the REST API; and you can add your own architecture documentation for the LLM judge to weigh. Findings only ever store bounded, non-sensitive samples (counts and object names).

System tables

Read via the assessment's SQL Warehouse. Different checks read different tables; the Used by column lists which layer agents draw on each — reflecting the checks that ship today.

Schema / table What it tells the agents Used by
system.information_schema.* Unity Catalog metadata: catalogs, schemata, tables, columns, constraints, privileges, tags, column masks, external locations, storage credentials, routines and registered models — the backbone of governance, format and security checks. All layers
system.access.audit Audit log of workspace actions — change control, access patterns, and who did what. OrchestrationAnalyticsAIML
system.access.table_lineage Table-to-table lineage, used to trace ingestion entry points and data-flow coverage. IngestionStorageProcessingOrchestrationAnalyticsML
system.billing.usage DBU consumption — the basis for cost-attribution, tagging and cost-optimization checks. All layers
system.compute.clusters, system.compute.warehouses, system.compute.warehouse_events Compute inventory and warehouse lifecycle events — autoscaling, auto-stop, sizing and reuse signals. (Analytics uses the warehouse tables; the others use clusters.) IngestionProcessingOrchestrationAnalyticsML
system.query.history SQL query history, for query-performance, caching and warehouse behavior checks. IngestionStorageProcessingOrchestrationAnalyticsML
system.lakeflow.jobs, system.lakeflow.job_run_timeline, system.lakeflow.pipelines Jobs and pipelines plus their run timelines — orchestration, reliability, retries and monitoring signals. IngestionProcessingOrchestrationAnalyticsAIML
system.serving.endpoint_usage Model-serving endpoint traffic, for AI/ML serving, scaling and monitoring checks. AIML
system.ai_gateway.usage AI Gateway usage, for governed-endpoint, cost and token-caching checks. AI

REST API configuration (not data)

LLM-judged checks read configuration the system tables don't surface — Git source, notification settings, autotermination, continuous-vs-triggered, and so on — over the Databricks REST API:

  • Jobs, pipelines & clusters — their definitions and settings.
  • External locations — storage the workspace is configured to reach.
  • Secret scope names — presence of secret management (names only, never secret values).

The grant agents require

Grant required before agents can run. Because a Job runs as the app's service principal, a metastore admin must grant that principal SELECT on the system schemas the checks read. Several system schemas are also disabled by default and must be enabled first. Without the grant, checks that read those tables come back as Unknown.

Grant the app service principal read on these schemas:

GRANT SELECT ON SCHEMA system.information_schema TO `<app-service-principal>`;
GRANT SELECT ON SCHEMA system.access          TO `<app-service-principal>`;
GRANT SELECT ON SCHEMA system.billing         TO `<app-service-principal>`;
GRANT SELECT ON SCHEMA system.compute         TO `<app-service-principal>`;
GRANT SELECT ON SCHEMA system.query           TO `<app-service-principal>`;
GRANT SELECT ON SCHEMA system.lakeflow        TO `<app-service-principal>`;
GRANT SELECT ON SCHEMA system.serving         TO `<app-service-principal>`;
GRANT SELECT ON SCHEMA system.ai_gateway      TO `<app-service-principal>`;

A service principal can read the system tables broadly, but the REST configuration APIs return only objects the principal itself can see — so grant it visibility of the jobs, pipelines and clusters you expect to be assessed.

Uploaded documentation

Bring your own context

You can attach design docs and diagrams to an assessment — PDF, TXT, Markdown, Word, and images. The agents fold that in as extra evidence for the LLM judge, so intent that isn't visible in workspace telemetry can still count.

How it's used

  • Extracted text is inlined into the judge prompt (size-capped).
  • Images ride along as vision blocks (bounded in count and size).
  • Only LLM-judged checks see the docs; deterministic checks are unchanged.
  • With no docs uploaded, behavior is exactly as before.

Kept trustworthy

The judge is told that documentation describes intent and may be out of date, so it weighs uploads below hard workspace signals when the two disagree.

When a verdict relied on an upload, the judge cites the exact excerpt it used, and that citation is attached to the finding so a reviewer can verify it.
