Getting started

Deploy the tool as a Databricks App, then run your first assessment.

Prerequisites

You'll deploy from a machine with the Databricks CLI, into a serverless-enabled workspace.

  • The Databricks CLI (v0.285.0 or newer), authenticated to your workspace — check with databricks auth profiles.
  • uv, which builds the agents package during the deploy, and jq.
  • Node.js 20+ and Yarn only if you change the frontend — a pre-built copy ships with the repo.
  • Access to Apps, Lakebase, and a chat model serving endpoint (default databricks-claude-opus-4-8).
  • A SQL warehouse, and an existing Unity Catalog catalog for uploaded architecture documents, on which you have CREATE SCHEMA and MANAGE.
Two grants can't be self-provisioned. The agent Jobs run as the app's service principal, so whoever deploys needs the Service Principal: User role on it — granted once, right after the app is created (step 2 below). And the agents read Databricks system tables, so a metastore admin must grant that principal SELECT on the relevant system schemas — see System tables & signals for the exact list.

Deploy the app

Everything is one bundle in app/: the app, its Lakebase database, the docs Volume and the agent Jobs. The app's resources grant its service principal access to the Volume, the SQL warehouse and the model endpoint.

No local tools? Clone the repository as a Git folder in your workspace, open deploy_notebook.py on serverless compute, and click Run all. It runs the same steps below, as you, and prints the app's URL at the end.

With the CLI, run the commands from app/:

# 1. Save your two workspace-specific values (git-ignored)
cd app
mkdir -p .databricks/bundle/sandbox
cat > .databricks/bundle/sandbox/variable-overrides.json <<'JSON'
{ "docs_catalog": "<your_catalog>", "warehouse_id": "<sql-warehouse-id>" }
JSON

# 2. Create the app first (Databricks creates its service principal)...
databricks bundle deploy --select apps.waf_assessment -t sandbox --profile $DATABRICKS_CONFIG_PROFILE
#    ...then grant yourself "Service Principal: User" on it: Settings → Identity and
#    access → Service principals → app-… waf-assessment → Permissions

# 3. Deploy the rest (the agent Jobs) and start the app
databricks bundle deploy -t sandbox --profile $DATABRICKS_CONFIG_PROFILE
databricks bundle run waf_assessment -t sandbox --profile $DATABRICKS_CONFIG_PROFILE

The README has the notebook walkthrough and troubleshooting — see Deploying to Databricks. For local development against an isolated database, see CONTRIBUTING.md.

Run an assessment

Create it

Click Start New Assessment, then New Assessment. Name it, pick the architecture layers in scope, and set a cloud provider — the score only counts the layers you select.

Answer & review

Work through each pillar's questions — marking each Answer later, Open, In Progress, Completed, or Ignore — or let a layer's agent draft them, then review the evidence and set each status.

Attach documentation (optional)

Upload architecture docs and diagrams (PDF, TXT, Markdown, Word, images). The agents fold them into the LLM judge as extra evidence — see Uploaded documentation.

Score & plan

Open the Results tab for your score and pillar/layer breakdown, generate the prioritized backlog, and export a PDF (or JSON) to share.

Use the 📋 button in the header to switch between assessments, or to export one as JSON and import it elsewhere.
